# Harness Anti-Regression — 反退化闭环

> 依据 Mitchell Hashimoto 核心循环 + Anthropic 官方工程博客重建。
> Harness 的灵魂子系统。确保同样的错误不会发生两次。
> v1.2: 融合经验纠错三路径 + 修正标记格式

## Hashimoto 核心循环

```
错误发生 → 修正方案永久化进环境 → 同样的错误不会再发生
```

## 闭环流程

```
1. DETECT    — PostToolUseFailure hook 捕获: 错误类型+上下文+输入输出
2. ANALYZE   — self-evolution-engine 分析根因
3. EXTRACT   — 提炼规则模式
4. PERSIST   — 写入 ironlaw/feedback 记忆
5. ACTIVATE  — PreToolUse 自动加载
6. VERIFY    — 同类任务不再犯
```

## 经验纠错三路径 (v1.2)

经验/技能文件出错的修正入口有三条：

**路径A：被动触发（经验执行失败）**
```
用户遵循经验建议 → 执行失败/报错 → AI 识别经验内容有误 → 自动修正
```

**路径B：主动触发（版本变更自检）**
```
平台版本更新（或降级）→ 逐条验证经验在当前版本是否有效
  → 标记失效项 → 添加版本兼容性说明 → 报告
```

**路径C：工具缺陷触发（调用异常）**
```
AI 使用内置工具 → 工具行为异常/返回结果与经验描述不符
  → AI 确认不是自身调用错误 → 进入纠错流程 → 更新经验文件
```

### 修正标记格式（统一标准）
```markdown
<!-- Correction: YYYY-MM-DD | was: [旧内容] | reason: [错误原因] | fix: [修正内容] -->
```

### 修正流程（三路径共用）
```
1. 检测 — 识别到建议/经验导致了错误
2. 验证 — 确认内容确实有误（排除自身调用错误）
3. 修正 — 更新文件 + 打修正标记
4. 报告 — 汇总已验证/已标记失效条目
```

## 🔴 Harness 自修改保护协议

修改 [Harness] 条目（记忆）之前必须：
1. 查询依赖关系（谁引用此条目 / 此条目引用谁）
2. 检查修改是否导致引用失效
3. 检查是否与 ironlaw 冲突
4. 列出影响范围 → 确认后再修改

修改后验证：
1. 读取所有链接到该条目的条目
2. 逐条检查引用有效性 → 不一致则修正或标记 [待同步]
3. 写修改日志: timestamp + 变更摘要

## 铁律升级路径

| 级别 | 行为 | 升级条件 |
|------|------|---------|
| L1: 建议 | Stop hook 中提醒 | 首次发现模式 |
| L2: 警告 | PreToolUse 中警告但允许 | 同一模式复发1次 |
| L3: 阻断 | PreToolUse 中阻断 | 同一模式复发2次+ |
| L4: 铁律 | SessionStart 注入 + 自修改保护 | L3生效后稳定运行 |
