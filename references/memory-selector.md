# Harness Memory Selector — 精选规则 + 确定性路由

> 基于 Anthropic Claude Code 源码 memory selection 机制。
> v1.2: 融合确定性路由表（问题特征→优先源）

## 精选规则

每次用户查询后，手动执行：
1. 列出所有记忆（仅标题+首行）
2. 按原则选出≤5条：
   - 只选**确定**有用的
   - 对[user]和[project]类型**极度保守**
   - 匹配**问题本身是什么**，而非表面关键词重叠
   - 不重复选择之前轮次已返回的记忆
3. 逐条读取完整内容→注入上下文

## 确定性路由表 (v1.2)

在精选之前，先按用户问题的**确定性特征**路由到最可能相关的记忆源：

| 用户问题特征 | 优先查询的记忆/源 | 优先级 |
|-------------|----------------|:------:|
| 提到"报错""失败""不行""error" | [反馈] 排错经验 | 高 |
| 提到"怎么用""哪个工具""组合""模式" | [索引] 包与技能地图 / 工具模式 | 高 |
| 提到某个包/功能怎么配置 | [索引] 包与技能地图 | 高 |
| 提到网络问题/镜像源/下载慢 | [反馈] 网络排错 | 中 |
| 提到开发/编译/打包 | [项目] 相关快照 | 高 |
| 提到总结参数/包开关/工具限制 | [反馈] 平台参数备忘 | 高 |
| 不确定翻哪份 | 全部扫描看匹配（回到精选规则） | — |

> 路由表先行 → 精选规则兜底。两者不冲突。
