# 任务规划与执行系统 — 三层编排架构

> 纯编排方案：不依赖特定包实现，任何具备规划工具/协作看板/子Agent能力的平台均可落地。

---

## 一、三层架构总览

```
第一层：规划引擎（task_planner 类工具）
  用途：任务拆解、可行性评分、方法分析
  输入：任务描述 → 输出：阶段+步骤+权重

第二层：协作看板（multi_agent_collab 类工具）
  用途：创建会话、添加角色、分配任务(优先级)、追踪进度
  特性：依赖校验、僵尸会话清理、心跳监控、ETA修正

第三层：子Agent执行器（sub_agent_manager 类工具）
  用途：创建真实子Agent实例执行任务
  特性：异步派发、工作目录隔离、批量清理、超时重试
```

## 二、核心行为规则

### 规则0：并行优先原则（最高优先级）

任何任务在判断可拆成 **2 个及以上独立子任务**时，必须立即并行派发，不得串行等待。

独立子任务定义：**不依赖彼此输出、可同时开展**的工作。

### 规则1：自动桥接

```
assign_task → review(blocking=false) → link_sub_agent
```
每次看板分配任务，必须跟随真实子Agent派发并建立关联。

### 规则2：回复前自动轮询

每次回复用户前检查子Agent状态：新完成→附带通知；卡住（>5分钟）→提示用户。

### 规则3：聚合仪表盘

回复末尾附带：`📊 运行中X / 已完成Y / 异常Z`

### 规则4：批量清理

用批量销毁替代逐个销毁；全部完成后归档会话。

### 规则5：优先级标签

`high` 紧急修复 / `medium` 日常默认 / `low` 低频优化。

## 三、并行优先标准工作流

```
1. 判断：任务可拆成2+独立子任务吗？
   ├─ 是 → 跳到步骤3（跳过单步规划）
   └─ 否 → 单线程执行（规划引擎→执行）

3. create_session() → 创建看板
4. add_agent() × N → 添加角色
5. assign_task(priority=) × N → 一次性分配所有任务
6. （并行关键）review(blocking=false) × N → 所有子Agent同时启动
7. link_sub_agent() × N → 关联看板和真实执行
8. 【关键】立即回复用户，秒回，不阻塞
9. 后续每次回复前轮询检查完成状态
10. 批量清理 → 归档会话
```

## 四、并行判定标准

| 必须并行（不用问用户） | 不能并行（必须串行） |
|----------------------|---------------------|
| 功能模块互不依赖（UI/逻辑/音效） | 任务B明确依赖任务A的输出 |
| 代码审查 + 功能开发 | 同一文件的连续修改 |
| 文档编写 + 代码实现 | 编译→测试→修复循环链 |
| 多个独立bug修复 | — |
| 多个独立配置修改 | — |

**边界模糊时：默认按并行处理，宁可并行不错过。**

## 五、角色配置参考（统筹协调示例）

| 角色 | 职责 |
|------|------|
| 需求分析师 | 梳理需求、用户故事、验收标准 |
| 技术架构师 | 技术方案、选型、系统架构 |
| 项目经理 | 任务分解、排期、风险评估、资源协调 |
| 领域工程师×N | 按模块实现核心功能 |
| 测试与质量保障工程师 | 单元/集成/边界测试 |

**7 角色并行开发示例**：需求分析师(2任务) + 架构师(2任务) + 项目经理(1任务) + 动画状态机工程师 + 战斗逻辑程序员 + 特效工程师 + 测试工程师 → 一次派发 9 个任务并行推进。
