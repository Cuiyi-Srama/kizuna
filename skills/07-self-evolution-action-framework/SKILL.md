# 自进化行动框架 v1.0

> 属于规则体系。自批判发现问题，自进化执行修复。本框架是**行动层**。

## 架构定位

```
批判引擎（批判层）        本框架（行动层）
────────────────────    ──────────────────
扫描记忆库→发现版本堆积 →  触发合并/归档策略
扫描包列表→发现过期索引 →  触发索引更新
审查对话 →发现规则冲突 →  触发规则修订
用户说  →"该整理了"    →  选择目标模块执行
```

**批判只输出报告，行动由本框架接管。**

## 策略模块（可扩展）

### S1: 包索引自更新
- 触发: 包/技能/MCP 配置变更后
- 扫描: 包列表 + 技能目录 + 配置
- 对比: checksum `{pkgTotal}-{enabled}-{disabled}-{skills}-{mcp}`
- 行动: 更新索引记忆
- 限流: 同会话最多每30分钟一次

### S2: 记忆库版本清理
- 触发: 批判引擎报告"多条同主题记忆" 或 用户明确要求
- 扫描: 同类前缀 → 对比 createdAt + 内容覆盖度
- 行动: 旧版归档，最新版保留，更新索引
- 约束: 删除前需确认，不移活跃链接目标

### S3: 规则冲突修复
- 触发: 批判引擎报告"规则A与规则B存在优先级冲突"
- 扫描: 取出两条规则 → 逐条对比冲突点
- 行动: 在优先级更高的规则中追加仲裁条款
- 约束: 不删除被覆盖规则，只追加

### S4: 对话碎片整理
- 触发: 发现大量无标题/短对话
- 行动: 创建归档记忆 → 可选删除
- 约束: 删除前需用户确认

## 通用执行流程

```
输入（批判报告/事件触发器/用户指令）
  ↓
策略匹配（按S1~S4匹配最合适的模块）
  ↓
前置检查（反幻觉验证 + 依赖分析 + 限流）
  ↓
执行（扫描→对比→生成变更→执行）
  ↓
归档（写记忆记录操作 + 更新相关索引）
```

## 安全约束

1. 破坏性操作（删除记忆/文件、停用包）必须经用户确认
2. 非破坏性操作（更新/移动记忆、写索引）自动执行
3. 任何操作不得修改铁律层的记忆
4. 执行后必须写一条"[进化日志]"记录操作内容
5. 单次会话最多触发 3 次进化操作

## 与批判引擎的桥接

- 批判引擎输出格式: `[批判报告] 模块名 - 问题 - 建议策略(S1~S4)`
- 本框架读取批判报告 → 匹配策略 → 执行
- 桥接: 记忆链接 `批判引擎 → 本框架 (FEEDS)`

## 附录：外部资源优先搜索规则（强制）

> 在自己动手创造之前，必须先搜索外部开源社区的现成资源。

### 搜索渠道（优先级从高到低）

| 优先级 | 渠道 | 搜什么 |
|-------|------|-------|
| 1 | **平台市场** | skill、package、mcp、script |
| 2 | **GitHub** | 开源 skill/MCP 项目、工具库 |
| 3 | **npm/PyPI** | 通用工具库 |
| 4 | **社区/知识库** | 解法讨论、最佳实践 |

### 优质评判标准（6项至少4项通过）

| 维度 | 通过条件 |
|------|---------|
| 任务匹配度 | 核心功能覆盖 > 80% |
| 生态兼容性 | 与目标平台兼容 |
| 维护活跃度 | 6个月内更新过 |
| 代码/文档质量 | 完整文档 + 可用示例 |
| 许可证 | MIT/Apache/可商用 |
| 复杂度与依赖 | 零依赖或少依赖，插拔式 |

### 适配决策

```
找到候选 → 评判通过 → 直接用 ✅ / 改造后复用 🔧 / 淘汰 ❌（记录原因）
全部淘汰 → 才进入"先用现成→改造→重构"三级链
```

### 淘汰记录模板（必须）

```
淘汰 [资源名]
├── 任务匹配度: ❌ (只覆盖了 X%，缺少 Y)
├── 生态兼容性: ✅
├── 维护活跃度: ✅
├── 代码/文档质量: ❌ (README 只有 3 行)
├── 许可证: ✅
└── 复杂度与依赖: ❌ (依赖整套框架)
→ 最终判定：不适用，继续搜索
```
